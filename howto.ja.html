バリエーション


カスタムゲームは現在、ゲームプレイの独自の変更を作成することを可能にする*variations*をサポートしています。

カスタムゲーム


カスタムゲームでは、 api.getVariation() 現在のバリエーションを取得する。 ベースゲームでは、 default.
使える api.matchmakeToVariation(playerId, variation) プレイヤーをカスタムゲームの異なるバリエーションに接続します。 使用条件 default オリジナルにマッチする
変数名は1文字と32文字の間でなければなりません。 文字、数字、ハイフン、アンダースコアのみを含むことができます。
バリエーションタイトルを設定できます。 api.setClientOption(playerId, "customVariationTitle", "My Variation"). ドキュメントを表示 api.setClientOption または customVariationTitle 詳細については、.
プレーヤーデータベース値(設定済み) api.setPlayerDbValue永続通貨を含む) すべてのバリエーションで共有 あなたのカスタムゲームの, ので、ハブでプレイヤーが獲得する進行は、 1v1, 2v2等。 バリエーションごとに値が異なる場合は、キーのバリエーション名(例:) `wins_${api.getVariation()}`).

事例紹介


ClutchやContainment Breachなどのゲームのロビーアリーナに触発された例です。 ハブのバリエーションを作成します。 ()default) そして、2つの異なるmodesのためのバリエーション: ソロ ()1v1)およびDuos ()2v2) 

let initialised = false
const variation = api.getVariation()

tick = () => {
    if (initialised) {
        return
    }

    if (api.getBlock(0, 0, 0) === "Unloaded") {
        // チャンクをロードするのを待ちます
        return
    }


    if (variation === "default") {
        // プレイヤーにマッチするプラットフォームを作成する
        api.setBlockRect([0, 0, 0], [2, 0, 2], "Red Concrete") // 1v1
        api.setBlockRect([4, 0, 0], [6, 0, 2], "Blue Concrete") // 2v2
    }
    initialised = true
}

onPlayerJoin = (playerId) => {
    if (variation === "default") {
        api.setPosition(playerId, 3, 5, -3)
        api.setCameraDirection(playerId, [0, 0, 1])
    }
    else if (variation === "1v1") {
        api.setClientOption(playerId, "customVariationTitle", "Solos")
    } else if (variation === "2v2") {
        api.setClientOption(playerId, "customVariationTitle", "Duos")
    }
}

// すでにマッチしている人にはマッチしない
/** @type {Record<PlayerId, boolean>} */
const playerHasMatchmade = {}

onBlockStandStart = (playerId, _x, _y, _z, blockName) => {
    if (variation !== "default") {
        return
    }
    if (playerHasMatchmade[playerId]) {
        return
    }

    if (blockName === "Red Concrete") {
        api.matchmakeToVariation(playerId, "1v1")
        playerHasMatchmade[playerId] = true
    } else if (blockName === "Blue Concrete") {
        api.matchmakeToVariation(playerId, "2v2")
        playerHasMatchmade[playerId] = true
    }
}

ワールド


世界が自分のロビーにいるため、バリエーションに可能性はありません。 しかし、カスタムゲームをテストするには、ロビーコードを特定のバリエーションとしてリロードできます。 これを行うには2つの主要な方法がありますが、どちらも少なくともCoderの権限を持っているか、より高い必要があります。
  • コードエディタで、3つの点を右クリックして開きます More Options メニューここでは、バリエーションを入力して、そのバリエーションとしてテストするためにロビーコードをリロードすることができます
  • コードが実行される場合 api.matchmakeToVariationそのバリエーションにリロードしたいとお聞きします。

プラグイン


ファーストパーティプラグインは、再利用可能なワールドコード機能を提供します。 プラグインをインポートする @plugins/<name> エントリーファイルまたは別のプロジェクトで file: 
import { setTimeout, getRandomItem } from "@plugins/helpers"
import { debugLog } from "@plugins/debug"

プラグインのインポートもコールバックをロードします。 独自のコードで同じ名前でコールバックを実行する前に、プラグインコールバックを実行します。 tick コールバックrun: 
import { setTimeout } from "@plugins/helpers"

tick = () => {
    /* ティックコード */
}

コールバックが値を返す場合、コールバックの戻り値がプラグインの上で優先されます。 事故による有用なプラグインのリターンを交換しないでください。特にコールバックなど onPlayerChat そして、 onRespawnRequest.
プラグインは他のプラグインをインポートすることができます。 依存関係が自動的にロードされるので、インポート @plugins/sessionBasedGame また、必要なヘルパーをロードします。

利用可能なプラグイン


  • @plugins/helpers エクスポート setTimeout, setInterval, clearTimeout, clearInterval, forceLoadChunk, randomInt, shuffleArrayと getRandomItem.
  • @plugins/debug エクスポート debugLog.
  • @plugins/sessionBasedGame ロビー・ツー・ゲーム・ライフサイクル、チーム、スペクター、マップ・ロード、オプション・マップ・投票、オプション・チーム選択、自動ゲーム・リセットを提供します。
エディタのオートコンプリートと既読のプラグインソースファイルは、最新のエクスポートとオプションタイプのリファレンスです。

SessionBasedGameを造る


使用条件 @plugins/sessionBasedGame このloopに従うチームゲームのため:
  1. ロビーをロードし、プレーヤーを待ちます。
  2. 必要に応じて、プレイヤーはチームを選択し、マップの投票を行います。
  3. 選択したマップをプレイエリアにコピーし、チームを割り当てます。
  4. 1つのチームが残っているか、コードが勝者を選ぶまでゲームを実行します。
  5. 結果を表示し、ロビーをリセットし、次のカウントダウンを開始します。

世界のレイアウト


世界の未使用部分にロビーと各マップを作成。 プラグインはこれらの領域をテンプレートとして扱い、それらのいずれかをコピーします。 playAreaRect.
  • playAreaRect 現在のロビーや地図が配置されている目的地です。
  • lobby.source.rect それぞれ map.source.rect テンプレートビルドの絶対的な世界座標です。
  • ロビースポーン、マップチームスポーン、チームパッドの長方形は、最下のコーナーからオフセットされます playAreaRect絶対的な世界は調整しません。
  • ソースの長方形は、チャンクの境界に外側を丸めています。 テンプレートは、コピーされた領域が予測可能であるため、32ブロックのチャンク境界に整列するビルドを保持します。
  • すべてのロビーとマップソースは、内側に収まる必要があります playAreaRect.
  • 少なくとも2つのチームと1つのマップが必要です。

プレーヤーを排除し、ゲームを終了


デフォルトでは、プレイヤーは死ぬとチームに残ります。 排除ゲームのために、spectatorに犠牲者を回して下さい: 
onPlayerKilledOtherPlayer = (_killerId, victimId) => {
    game.getPlayer(victimId).startSpectating()
}

onMobKilledPlayer = (_mobId, playerId) => {
    game.getPlayer(playerId).startSpectating()
}

startSpectating() 1チームのみが残っているか確認し、自動的にゲームを終了します。 別の勝利条件が付いているゲームのために、呼出し game.makeTeamWin(team) その条件が満たされるとき。

カスタムプレーヤーの状態と行動


拡張する SessionBasedPlayer 各プレーヤーが付加的な状態かカスタマイズされたライフサイクルの行動を必要とするとき、そしてクラスをとして渡して下さい playerConstructor. この例は teams, maps, lobbyと playAreaRect constantsです。 
import { createGame, SessionBasedPlayer } from "@plugins/sessionBasedGame"

class GamePlayer extends SessionBasedPlayer<(typeof teams)[number], (typeof maps)[number]> {
    kills = 0

    startPlaying() {
        super.startPlaying()
        this.kills = 0
    }
}

const game = createGame({
    teams,
    maps,
    lobby,
    playAreaRect,
    playerConstructor: GamePlayer,
})

電話番号 super.startPlaying() or super.startSpectating() プラグインがインベントリー、健康、可視性、ビルド権限をアップデートし、検出を勝ち取るために、これらのメソッドをオーバーライドするとき。

エントリーファイル全体を貼り付ける


使用条件 index.js コードエディタで。 以前の例を block 全体に置き換えます: それはすべての定数を含んでおり、すぐにゲームを作成します。 チームパッドのリクエストは、少なくとも2人のプレーヤーでテストするので、テスト時に異なるパッドを選択します。 
import { createGame, SessionBasedPlayer } from "@plugins/sessionBasedGame"

/* コンテンツ */
const SCORE_TO_WIN = 10
const ROUND_SECONDS = 180
const PLAYERS_PER_TEAM = 4

/* 世界のレイアウト */
/* この例のスコアリングとHUDは、teams:赤と青の2つのteamsのために書かれています。 */
const teams = [
    { name: "Red", maxPlayers: PLAYERS_PER_TEAM, colour: "#ff5555" },
    { name: "Blue", maxPlayers: PLAYERS_PER_TEAM, colour: "#5555ff" },
]

const maps = [
    {
        name: "Castle",
        icon: "Stone Bricks",
        source: { rect: [[320, 0, 0], [351, 31, 31]] },
        teams: {
            Red: { spawn: [6, 2, 16], spawnFacing: [1, 0, 0] },
            Blue: { spawn: [26, 2, 16], spawnFacing: [-1, 0, 0] },
        },
    },
    {
        name: "Courtyard",
        icon: "Grass Block",
        source: { rect: [[384, 0, 0], [415, 31, 31]] },
        teams: {
            Red: { spawn: [16, 2, 6], spawnFacing: [0, 0, 1] },
            Blue: { spawn: [16, 2, 26], spawnFacing: [0, 0, -1] },
        },
    },
]

/* ラウンド状態 */
const scores = { Red: 0, Blue: 0 }
let roundEndsAt = 0
let resultText = ""

class ArenaPlayer extends SessionBasedPlayer {
    kills = 0

    startPlaying() {
        super.startPlaying()
        this.kills = 0
        api.setClientOptions(this.playerId, {
            secsToRespawn: 3,
            respawnButtonText: "Respawn",
            usePlayAgainButton: false,
        })
    }

    onRespawnRequest() {
        const position = super.onRespawnRequest()
        if (this.team !== null) {
            /* また、ラウンドスタート時に実行します。 スロットを設定すると、再発は機器を複製することはできません。 */
            api.setItemSlot(this.playerId, 0, "Iron Sword")
            api.setItemSlot(this.playerId, 46, `${this.team.name} Wood Helmet`)
            api.setItemSlot(this.playerId, 47, `${this.team.name} Wood Chestplate`)
            api.setItemSlot(this.playerId, 48, `${this.team.name} Wood Gauntlets`)
            api.setItemSlot(this.playerId, 49, `${this.team.name} Wood Leggings`)
            api.setItemSlot(this.playerId, 50, `${this.team.name} Wood Boots`)
        }
        return position
    }
}

const game = createGame({
    teams,
    maps,
    playerConstructor: ArenaPlayer,
    playAreaRect: [[0, 0, 0], [31, 31, 31]],
    lobby: {
        source: { rect: [[256, 0, 0], [287, 31, 31]] },
        spawn: [16, 2, 16],
        spawnFacing: [0, 0, 1],
        teamPads: {
            Red: {
                rect: [[4, 1, 14], [6, 1, 16]],
                emptyBlock: "Red Concrete",
                fullBlock: "Red Ceramic",
            },
            Blue: {
                rect: [[25, 1, 14], [27, 1, 16]],
                emptyBlock: "Blue Concrete",
                fullBlock: "Blue Ceramic",
            },
        },
    },
    mapVotingEnabled: true,
    maxSpectators: 4,
    emptyLobbyStartInSecs: 30,
    fullLobbyStartInSecs: 5,
    gameResetInSecs: 10,
    onStart: () => {
        scores.Red = 0
        scores.Blue = 0
        resultText = ""
        roundEndsAt = api.now() + ROUND_SECONDS * 1000
        api.broadcastMessage(`First team to ${SCORE_TO_WIN} kills wins!`)
        game.checkWin()
    },
    onFinish: (winningTeam) => {
        resultText = `${winningTeam.name} wins! Red ${scores.Red} - Blue ${scores.Blue}`
        api.broadcastMessage(resultText)
        /* 結果画面の戦闘および明確な装置。 */
        for (const player of game.getPlayers()) {
            player.startSpectating()
        }
    },
    getRightInfoText: (player) => {
        if (game.gamePhase === "beforeGame") {
            return [
                "TEAM DEATHMATCH\nChoose a team on the coloured pads.\nVote for a map in the shop.\n",
                ...game.getStartingInText(),
            ]
        }
        if (game.gamePhase === "gameFinished") {
            return `${resultText}\nNext round soon!`
        }
        const secondsLeft = Math.max(0, Math.ceil((roundEndsAt - api.now()) / 1000))
        const clock = secondsLeft > 0 ? `${secondsLeft}s left` : "Sudden death: next team lead wins!"
        const role = player.team === null ? "Spectating until next round" : `${player.team.name} team`
        return `TEAM DEATHMATCH\n${role}\nRed ${scores.Red} - Blue ${scores.Blue}\nTarget: ${SCORE_TO_WIN}\n${clock}\nYour kills: ${player.kills}`
    },
})

function checkScoreWin() {
    if (game.gamePhase !== "inGame") {
        return
    }
    for (const team of teams) {
        const otherName = team.name === "Red" ? "Blue" : "Red"
        const reachedTarget = scores[team.name] >= SCORE_TO_WIN
        const leadsAfterTime = api.now() >= roundEndsAt && scores[team.name] > scores[otherName]
        if (reachedTarget || leadsAfterTime) {
            game.makeTeamWin(team)
            return
        }
    }
}

tick = () => {
    checkScoreWin()
}

onPlayerKilledOtherPlayer = (killerId, victimId) => {
    if (game.gamePhase === "inGame") {
        const killer = game.getPlayer(killerId)
        const victim = game.getPlayer(victimId)
        if (killer.team !== null && victim.team !== null && killer.team !== victim.team) {
            killer.kills++
            scores[killer.team.name]++
            checkScoreWin()
        }
    }
    return "keepInventory"
}

onMobKilledPlayer = () => {
    return "keepInventory"
}

onPlayerDropItem = () => {
    return "preventDrop"
}

ピースが接続する方法


  • プラグインのインポートは、その参加を登録します, 残します, チェック, チームパッド, ショップ投票, チャット, そして、コールバックを予約. これらのプラグインコールバックmanuallyを呼び出しないでください。 tick そして、コールバックが自動的に実行されるのを殺します。
  • startPlaying() 各参加者のラウンドごとに1回実行します。 個人的なキルをリセットし、ベースの実装を呼び出して、健康、チームの可視性、友好的な火災ルール、およびスポーーンの位置を復元します。 onStart プレイヤーが開始した後、共有スコアと期限をリセットします。
  • 死は自分のチームでプレイヤーを離れるので、プラグインはマップのスポーンでそれらを予約しました。 プレイヤー方法 onRespawnRequest() 機器を復元し、ベーススポーン位置を返します。 その位置を戻すことは不可欠です。別のグローバルリスペーンコールバックは誤ってオーバーライドできます。 モブと環境死はポイントを付与しません。
  • getRightInfoText(player) 自分の個人を含むそのプレーヤーのためのスコアボードを構築します。 kills カウント。 プラグインは、このHUDを秒後に更新します。
  • makeTeamWin 呼び出し前のフェーズを変更する onFinishつまり、全員を分光器に変換すると、別の勝利をトリガーできません。 スコアは結果スクリーンの間に目に見えるまま;プラグインは10秒後にロビーをリロードし、その後、 onStart 次の試合をクリアします。 プラグインは、接続解除後に1つのチームのみが残っているときにラウンドを終了します。

機能的なNPCs


An interactable エンティティは、攻撃ではなく、プレイヤーが目指し、相互作用する1つです。 火災の相互作用 onPlayerAltAction エンティティをターゲットに、クロスヘアはキーを押すプレーヤーを指示します。
  1. interactable エンティティは、エンティティを自分で受け取り、 canAttack 何かを行うためのものではありません。 エンティティにはまだ土地を現します。それでスイングや撮影は何もしません。
  2. alt アクションは消費されるので、NPC を通して保持されたブロックは置かれず、保留可能は費やされません。
  3. interactionPrompt キーの横にラベルを取り替えて下さい。 デフォルトで設定されていないまま Interact. エンジンがキー自体を引くので、どのボタンが押すのではなく、相互作用が何かを記述して下さい。
  4. テキストや CustomTextStylingなので、 translationKey あなたの世界が翻訳されている場合。
  5. モブだけでなく、エンティティに動作します。
  6. タップがプロンプトを必要としないタッチスクリーンには何も描画されません。 インタラクション自体はまだ機能します。

ショップキーパー


let shopkeeperId = null

tick = () => {
    if (shopkeeperId !== null) {
        return
    }

    if (api.getBlock(8, 4, 8) === "Unloaded") {
        // NPCを置く前に荷を積むためにチャンクを待って下さい
        return
    }

    shopkeeperId = api.attemptCreateMeshEntity("Person", {
        size: 1,
        pose: "standing",
        textures: { head: "trader_black" },
    }, "Blacksmith")

    if (shopkeeperId === null) {
        // エンティティの限界は到達しました
        return
    }

    api.setPosition(shopkeeperId, 8, 5, 8)

    // NPCのピック可能な状態を保つことができるので、canAttackは離れることができます
    api.setTargetedPlayerSettingForEveryone(shopkeeperId, "canAttack", false)
    api.setTargetedPlayerSettingForEveryone(shopkeeperId, "interactable", true)
    api.setTargetedPlayerSettingForEveryone(shopkeeperId, "interactionPrompt", "Buy Gear")
}

onPlayerAltAction = (playerId, x, y, z, block, targetEId) => {
    if (targetEId === shopkeeperId) {
        // 店を開いたか、閉鎖したキーを押し続けるか、またはキーを押して下さい
        api.openShop(playerId, false)
    }
}

プレイヤーは対話キーと Buy Gear ブラックスミスを眺めながら、クロスヘアで、ショップをオープン。 NPCのヒットはまったくありません。

保有キーの監視


onPlayerAltAction 対話キーが保持されている間、約50〜150ms毎の発射を続けます。 既に開店している店を再開することは何もないので、上記の例ではガードを必要としません。 アイテムを付与する相互作用, 通貨を充電したり、会話を事前に請求することは意図しない, そして、繰り返すitselfを飲みなければならない: 
const INTERACT_COOLDOWN_MS = 800
const lastInteractAt = {}

onPlayerAltAction = (playerId, x, y, z, block, targetEId) => {
    if (targetEId === questGiverId) {
        const now = api.now()
        if (now - (lastInteractAt[playerId] ?? 0) >= INTERACT_COOLDOWN_MS) {
            lastInteractAt[playerId] = now
            sayNextLine(playerId)
        }
    }
}

onPlayerLeave = (playerId) => {
    delete lastInteractAt[playerId]
}

800msは、保持されたキーを飲み込むのに十分な長さで、2つの審美的なプレスが2回カウントします。

回路図全体をロードする


function loadSchematic(schematicPath, destination) {
    const [width, height, depth] = api.getSchematicDimensions(schematicPath)
    const [destX, destY, destZ] = destination

    for (let x = 0; x < width; x += 32) {
        for (let y = 0; y < height; y += 32) {
            for (let z = 0; z < depth; z += 32) {
                api.setChunkAsSchematic(
                    schematicPath,
                    [x, y, z],
                    [destX + x, destY + y, destZ + z],
                )
            }
        }
    }
}
