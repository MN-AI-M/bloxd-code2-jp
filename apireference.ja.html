addUiRequest

プレイヤーが右上隅に応答するようにリクエストを追加します。 例: tprequest を受け入れるか拒否する。
onUiRequestRespondedを使用して応答を処理します。
Usageの例: 
const myRequestId = api.addUiRequest(playerId, {
  type: "standard",
  title: "Do you want to join the game?",
}, 5000)

onUiRequestResponded = (playerId, uiRequestId, response) => {
  if (uiRequestId === myRequestId) {
    api.log(response)
  }
}

パラメーター:

パラメーター型説明
playerIdPlayerIdプレイヤーのIDは、リクエストを追加する。
parametersUiRequestClientParametersリクエストのパラメータ。
timeoutAfterMsnumberリクエストが自動的に削除されるタイムアウト。 onUiRequestRespondedは応答が与えられません。

戻り値:

UiRequestId

リクエストのID。 deleteUiRequestまたはonUiRequestRespondedとの相互参照に渡して下さい。

addUiRequestPopup

ポップアップの形で回答するためにプレーヤーのリクエストを追加します。 このブロックは、プレイヤーが応答するまで、他のことをやってからブロックします。
onUiRequestRespondedを使用して応答を処理します。
Usageの例: 
const myRequestId = api.addUiRequestPopup(playerId, "Do you want to join the game?")

onUiRequestResponded = (playerId, uiRequestId, response) => {
  if (uiRequestId === myRequestId) {
    api.log(response)
  }
}

パラメーター:

パラメーター型説明

戻り値:

setWalkThroughRect

プレイヤーが特定の矩形内にある(またはウォークスルーしない)オクセルを歩くことを可能にします。
普通の固体で、シースルーではないブロックのために、プレーヤーはブロックの中の間わずかな視覚のグリッチを経験します。
pos1 と pos2 を [0, 0, 0] にセットして 0, 0, 0 のパスだけを作ることができます。
CANT_WALK_THROUGH の rect に上記の部屋がある場合、それらのために固体を回す voxel の中で立っているプレーヤーはそれに持ち上げられます。
それらがどこにいるか滞在できるようにするには、その免除を削除する前にブロックを削除します。

パラメーター:

パラメーター型説明
playerIdPlayerId
pos1number[]キューボイドの1角。 フォーマット [x, y, z]
pos2number[]立方体の右上隅。 フォーマット [x, y, z]
updateTypeWalkThroughType更新の種類。 リベットの固形を作るか、または歩くことができるかどうか。 DEFAULT_WALK_THROUGHを渡すと、そのリクットのウォークスルー設定を無効にします。

setWalkThroughType

プレイヤーがブロックの種類を歩くことを可能にします。 普通の固体で、シースルーではないブロックのために、プレーヤーはブロックの中の間わずかな視覚のグリッチを経験します。
上記の部屋がある場合、それらのために固体を回すブロックの中に立っているプレーヤーはそれに持ち上げられます。 それらがどこにいるか滞在できるようにするには、そのタイプを再び固める前にブロックを削除します。
